# 饮片炮制记录台

一条记录是一整包炮制文书，里面是工序数组，不是拆成多列指标的普通表单。清炒温度和时长不在范围内就不能放行。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3193 |
| 接口 | http://localhost:8193 |
| PostgreSQL | localhost:54393 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| processor | herb123456 | 炮制员（可写记录、建调拨单、确认他人调拨单、开账号） |
| checker | check123456 | 质检员（只读：可翻记录、调拨单与流水） |

另需一名炮制员做双岗确认时，由现有炮制员在「炮制记录」页「另开账号」处新建一个炮制员账号（也可建质检员账号）。

## 厂际调拨

顶栏「厂际调拨」进入专属落地页，含待确认、已生效、调拨流水三段（不是总表旁的按钮）。

- 炮制员建调拨单：源厂名、目标厂名、饮片名。
- 双岗确认：必须由**另一名**炮制员点确认，建单人不能自己确认；质检员不能建、不能确认，只能翻阅。
- 未确认（待确认）期间，源厂、目标厂按厂名筛选结果都不变。
- 确认生效后，该味在源厂的最新一行划归目标厂：源厂按厂名筛藏起该行，目标厂筛可见。筛选条件全部由服务端按 `?factory=` 计算。
- 建单与确认都写入调拨流水。

## 启动

```bash
cd projects/14-herb-process-record
docker compose up --build
```

## 验收

1. processor 登录后，甘草（甲厂）为放行，黄芩（乙厂）为未放行（温度过低）。
2. 再写一条温度 200 的清炒，结论仍是未放行。
3. checker 看不到写入按钮，也不能建/确认调拨单，但能看待确认、已生效与调拨流水。
4. processor 另开炮制员账号 processor2。
5. processor 建调拨单：甘草 甲厂 → 乙厂；未确认时按甲厂筛仍能看见甘草，乙厂看不见。
6. processor 自己点确认被拒（403）；退出换 processor2 登录后确认，单生效。
7. 生效后按甲厂筛藏起甘草最新行，按乙厂筛能看见甘草；调拨流水含「建单 processor」与「确认 processor2」两条。
